# kaku — AI小説執筆支援ツール

AIを**執筆者ではなく「編集者」+「執筆者のためのスマートな外部記憶装置」**として使う、
小説執筆用のデスクトップアプリです。

**AIは本文を書きません。** これは制限ではなく、このアプリの定義です。
AIがやるのは ①アイデア出しの補助 ②設定管理 ③誤字脱字チェック ④レビューと改善提案 の4つで、
指摘や提案は必ず採否をあなたに委ねます。原稿へ勝手に書き込むことはありません。

原稿と設定は**普通のMarkdownファイル**として保存されます。アプリを捨てても、
データはあなたの手元にテキストのまま残ります。

## できること

| | 内容 |
|---|---|
| **書く** | CodeMirror 6 のエディタ。日本語IMEでの長文入力を実機検証済み(12,453字・IME変換281回で欠落なし)。行番号・ルーラー・任意字数での折り返し。自動保存+保存前に1世代バックアップ。配色はライト/ダーク/デバイス設定依存 |
| **設定を引く** | 設定(codex)の名前と別名を本文中で自動ハイライト。Ctrl+クリックで右ペインに内容を表示。書きながら設定を読める |
| **相談する** | 対象の本文と、名前が一致した設定を添えてAIに相談。**何を渡すかは実行前に一覧で見え、その場で外せます**。定型の文例をクリックで挿入。相談は `ideas/` にMarkdownで残せます |
| **校正する** | ①**表記ゆれ**: 設定に登録された名前と1文字違いの語を機械照合で検出(LLM不要・即座・決定的)。「架純」に対する「佳純」のような誤変換を、設定を知らない一般の校正ツールより確実に見つけます ②**誤字脱字**: LLMによる検出 |
| **レビューする** | 5つの観点(文章品質/構成・テンポ/キャラクター/設定整合性/読者視点)で引用つきの指摘と全体講評。**引用が本文に実在するかを機械照合**して幻覚を落とします。結果は `reviews/` に残せます |
| **設定を育てる** | 本文から未登録の固有名詞を抽出して追加候補にします。「黒木龍一/黒木/龍一/教授」のような複数の呼び名は1件にまとめ、別名として提案します。登録は選んだものだけ |
| **探す** | 開いているファイル内の検索(Ctrl+F)と、プロジェクト全体の全文検索。索引は使い捨てで、壊れても作り直します |
| **切り分ける** | 長くなったシーンの分割を**提案**します。切れ目の前後を並べて見せ、採用したものだけを適用。**本文は1文字も変えず**、元のファイルはゴミ箱へ退避します |
| **消さない** | 削除はプロジェクト内のゴミ箱へ移すだけです。アプリから原稿を永久に失う操作はありません |

ルビは `｜漢字《かんじ》` の一形式で書けます(カクヨム・なろう・青空文庫にそのまま貼れます)。

### まだ無いもの

縦書きプレビュー、版管理UI、相関図、作品全体レビュー、AI本文執筆。
詳しくは [docs/05-roadmap.md](docs/05-roadmap.md) を見てください。

## 入れる

**[Releases](https://github.com/shihou1115/kaku/releases/latest) から落とせます。**
64bit の Windows 10/11 用です。開発環境(Node / Rust)は要りません。

| ファイル | |
|---|---|
| `kaku_1.0.0_x64-setup.exe` | NSIS形式。**普通はこちら** |
| `kaku_1.0.0_x64_en-US.msi` | MSI形式。組織で配布する場合など |

WebView2 が要りますが、Windows 11 には標準で入っています。

**コード署名をしていないため、実行時に SmartScreen の警告が出ます。**
「詳細情報」→「実行」で進めてください。署名証明書を持っていないので、当面この形になります。
気になる場合は、下の手順でソースからビルドしてください(同じものができます)。

AI機能を使うには接続先の設定が要ります(→「AIの接続」)。
**AI未接続でも、執筆・設定管理・表記ゆれ検出は動きます。** まず触るならアプリ内の「サンプルを試す」から。

## ソースから動かす

### 必要なもの

| | 検証済みバージョン |
|---|---|
| Node.js | 22.22.3(npm 10.9.8) |
| Rust | 1.96.0(rustc / cargo) |
| OS | Windows 10/11。コードはクロスプラットフォームを壊さない範囲で書いていますが、**動作確認はWindowsのみ**です |

Tauri 2 のビルドには追加の前提があります([Tauri公式の前提条件](https://tauri.app/start/prerequisites/))。
Windowsでは WebView2(Windows 11には標準搭載)と Microsoft C++ Build Tools が必要です。

### 開発ビルドで起動

```bash
npm install
```

```bash
npm run tauri dev
```

### インストーラを作る

```bash
npm run tauri build
```

`src-tauri/target/release/bundle/` に msi と exe(NSIS)ができます。
**コード署名はしていない**ので、実行時に SmartScreen の警告が出ます。

### テスト

```bash
cargo test --manifest-path src-tauri/Cargo.toml
```

```bash
npm test
```

実機のLLMが要るテストは `#[ignore]` にしてあります。動かす場合は LM Studio を起動して:

```bash
cargo test --manifest-path src-tauri/Cargo.toml --test review_moralizing -- --ignored --nocapture
```

## AIの接続

OpenAI互換API(`/v1/chat/completions`)を1本だけ使います。プロバイダごとの分岐は持ちません。

**推奨はローカルLLM**です。理由は費用ではなく、①原稿が外部へ出ない ②題材によって拒否されない、の2つです。

ローカルなら **LM Studio**(既定の接続先 `http://localhost:1234/v1`)か **Ollama**。
**はじめてなら LM Studio** を勧めます。モデルの入手からサーバー起動まで画面上で完結し、
コマンド操作が要りません。Ollama も OpenAI互換なので、接続先を合わせれば同じように動きます。

クラウド(OpenAI・OpenRouter 等)も、OpenAI互換であれば接続先URLとモデル名の差し替えだけで動きます。

**APIキーはアプリに保存しません**(起動のたびに入力してください)。

### 知っておくと結果を誤解しないこと

アプリ内の**ヘルプ**(ヘッダーの「?」)に同じ内容があります。実測に基づく要点だけ:

- **犯罪・暴力・性描写を扱うなら、モデルの選定に注意**が要ります。ただし影響は用途で違います。
  校正・設定抽出・レビューといった「与えられた文章を分析する」用途は**検閲ありのモデルでも通ります**。
  拒否されやすいのは「展開案を書かせる」ような**生成寄りの依頼**です
- **拒否の形はエラーではなく「応答が1文字も返らない」**です。アプリ側でも検出して伝えますが、
  無反応に見えたら検閲を疑ってください
- **応答が返らない・打ち切られる場合はコンテキスト長を増やす**、**遅い場合は並列数を下げる**。
  必要な値は本文の長さとモデルで変わるので、決まった推奨値はありません
- 実用には **30 tok/s 程度の速度**が目安です

## データの形

プロジェクトは**ただのフォルダ**です。アプリは独自DBに取り込みません。

```
作品フォルダ/
├─ manuscript/   原稿(シーン単位のMarkdown)
├─ codex/        設定(characters / locations / items / terms / notes)
├─ plot/         プロット
├─ ideas/        AI相談の記録(残すと決めたものだけ)
├─ reviews/      AIレビューの講評(残すと決めたものだけ)
└─ .app/         アプリ専用(バックアップ・ゴミ箱・ログ)。消しても再生成されます
```

各ファイルは YAML フロントマター + 本文です。アプリが解釈するのは
`type` / `title` / `aliases` / `description` の4つだけで、**それ以外の項目は読み書きで壊しません**。
他のエディタで直接編集しても構いません。

詳細は [docs/03-data-format.md](docs/03-data-format.md)。

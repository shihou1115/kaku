## 0. なぜ今やるのか

引き継ぎレビュー(05-roadmap §10)では、テストの無い場所から**原稿を失う・壊す不具合が3件**、
**失敗を「指摘なし」と見せる誤報告が5件以上**出た。どれも単体テストが緑のまま潜んでいた。
同じ「型」の不具合が、まだ見ていない機能にも潜んでいると考えるのが自然である。

| 何がテストされていないか | 規模 |
|---|---|
| React の画面部品(AiPanel・ReviewPane・ProofreadPane・Editor・NewFileDialog ほか17本) | 約3,800行。テスト0件(判断を純関数へ出した部分だけテストあり) |
| `templates.rs`(580行・5件)/ `search.rs`(366行・7件)/ `mentions.rs`(204行・5件)/ `ailog.rs`(147行・2件) | 行数に対してテストが薄い |
| ファイル名・パスの検証 | 改名・新規作成・フォルダー作成とも、入力の検証がほぼ無い |
| 実機でしか起きない事象(二重起動・IME・同期フォルダー・長いパス) | 確かめる仕組みが無い |

## 1. 探す当たり: これまでに出たバグの型

見つかったバグを「型」に分け、**同じ型が潜みそうな場所**を当たる。

| 型 | 実際に出た例 | 同じ型が潜みそうな場所 |
|---|---|---|
| **位置ずれ**(文字の数え方の食い違い) | CRLF の原稿で「置換」が別の文字を書き換えた | サロゲートペア(𠮷)・異体字セレクタ(葛󠄀)・結合文字・BOM を含む本文。位置を返すすべての機能 |
| **誤報告**(失敗が0件・成功に見える) | 拒否・形式不備・中止を「指摘なし」と表示 | 検索0件・言及0件・表記ゆれ0件・別名追加0件の表示 |
| **画面と実体の食い違い** | モデル欄が実際と違うモデルを表示 | 表示設定・資料の選択・会話の履歴・参照ペイン・ツリーの表示名 |
| **順序と割り込み**(非同期) | 保存の二重実行、応答待ちの間に中止が効かない | AI 処理中のファイル切替・閉じる・二重起動 |
| **経路の取りこぼし**(不変条件を一部の経路だけで守る) | アプリ専用領域の判定が改名・複製で素通り | ファイル名の検証、読み取り専用の扱い |
| **OS とファイルシステムの規則** | 大文字小文字・末尾の点・改行コード | `:`(NTFS の代替データストリーム)・予約名・長いパス・NFD・同期フォルダー |
| **書き換えの副作用** | 改名のリンク追随が開いている本文を変えた | フロントマターの書き換え(別名追加)・テンプレート展開・分割の見出し |

## 3. テスト項目

優先度:
- **P1**: 原稿・設定を失う、壊す。または誤った結果を正しいように見せる
- **P2**: 期待どおりに動かないが、回避できる
- **P3**: 見た目・性能・使い勝手

手段(§4 で詳しく書く): **単**=単体テスト / **乱**=乱数入力で性質を確かめる / **差**=2つの実装の突き合わせ /
**通**=実ファイルでの通しテスト / **擬**=擬似AIサーバー / **実**=実機(computer use) / **計**=計測

★ は §2 の疑いがある項目。

## 4. 手段と道具

**依存は増やさない**(proptest などを入れない)。今ある道具で組む。

- **単体テスト**: Rust は各モジュールの `tests`、TS は vitest。画面部品の判断は、これまでどおり
  **純関数に出してから**テストする(`saveFlow.ts` / `resultLabel.ts` / `modelChoice.ts` と同じ流儀)
- **乱数入力(固定シード)**: 小さな乱数生成器を自前で書き、シードをテスト名に残す。
  落ちたら、そのシードを固定の回帰テストにする
- **2つの実装の突き合わせ**: 同じ規則を Rust と TS の両方で持つもの(言及・ルビ)は、
  **共通の入力表**(例: `src-tauri/tests/data/unicode_cases.json`)を両方のテストから読み、
  同じ期待値で確かめる
- **実ファイルの通しテスト**: `src-tauri/tests/*.rs` と同じく、使い捨てのフォルダーで行う。
  作業フォルダー名は連番を混ぜる(並列実行で衝突した前例がある)
- **擬似AIサーバー**: `lib.rs` の `ai_run_tests` を広げる(台本・黙り込み・途中で黙るは既にある)
- **実機(computer use)**: §6 の安全策を必ず守る
- **計測**: 時間は同じ操作を3回測って中央値。容量はファイルサイズの合計
- **テストが効いているかの確認**: 見つけたバグを直したら、**直した箇所を元に戻すとテストが
  落ちること**(変異)を必ず確かめる。引き継ぎレビューとその後の修正で30件余りこの方法を使い、
  テストの取りこぼしを1件見つけた
- **乱数の入力を作るときは、生成器そのものが働いているかも確かめる**(P3 の F1)。JS で掛け算の
  LCG を書くと、積が 2^53 を超えて下の桁が死に、ほとんど同じ入力しか作らない。等価のテストが緑の
  まま変異を1つも捕まえなかった。xorshift32(`>>> 0` で32ビットに保つ)を使い、**当たりの数の下限**
  など「比べた量」も確かめる
- **変異のときにテストを名前で絞るなら ASCII で絞る**。日本語のテスト名で `-t` を渡すと、コマンドの
  文字コードで化けて1件も走らず、変異を「見逃した」ように見える(P3 で起きた)
- **直したら全体を走らせてから commit する**。対象のテストと変異だけで commit し、別のテストが古い
  値を固定していたのを見落とした(P3 の a216984 → 4556141)
- **文書や表の書き換えは、シェルの文字列置換でしない**(Edit で行う)。Markdown のバッククォートが
  シェルのコマンドとして走り、正規表現の逃がしも崩れて、文書の1行目を壊した(P3。commit 前に
  git から戻した)。書き換えたら `git diff` で、変えたつもりの行だけが変わっているかを見る

B2・G1 の確認(2026-10-04)で分かったこと:

- **二重起動の防止はリリースビルドにしか入っていない**(開発版に入れると、インストール版で

  断られる。回り道もしない)。検証用のフォルダーは、**クリックだけでたどれる場所**に作る。

  作り(クイックアクセスの uggg から1つ上へ)、終わったら消した

  正しく写さないことがある。** 暗幕が無く、補足の文字が消えかけて見えた。見た目の判断に
  使うときは、.NET の画面コピー(`CopyFromScreen`)で**その部分だけ**切り出して確かめる

  本人の設定まで変わる
- **IME は computer use から入れられない**(半角/全角キーを送れず、Alt+` も効かない。
  タスクバーの入力モードはエクスプローラーなので操作できない)。変換中の振る舞い(F3)は
  本人に確かめてもらう
- 右クリックのメニューは**クリックした位置の少し下**に出る。ツリーは保存などで行がずれるので、
  右クリックの前に撮り直して行の位置を確かめる(違う行のメニューを開いたことがある)

- `<select>` を開いたときの一覧は、スクリーンショットでは黒く隠れる(別の窓として扱われる)。
  開いたまま**キー(上下と Enter)で選ぶ**。並びは名前順(テンプレートのジャンルなら SF・ファンタジー・
  ミステリ・恋愛・…・汎用)

  テンプレートを試すときは、**新しい名前のファイルだけを足し**(既存のものには触らない)、終わったら消す

  これを満たす形にする(ASCII やひらがなを含む名前は機械側で落ちる)
